# Python aggregation guard: combine_for_value / combine_for_rank plus four retrofits

Add a shared aggregation guard to the skill's Python scripts and retrofit the four
existing aggregation sites to use it.

Spec: docs/specs/004-aggregation-roles/plan.md sections 5.4, 6.3, 7.4 (ticket D of five).

This is the step that turns "roles exist" into "aggregation is checked". Without it the
vocabulary is available but nothing consumes it from the side of the codebase that
actually aggregates.

## READ THIS FIRST: nothing here is broken

All four sites are CORRECT today. Two of them sum an INTENSIVE column and are still
correct, and understanding why is the whole design of this ticket. Do not "fix" them.

The retrofit makes intent explicit; it must not change a single computed number.

## Design

## The API: intent at the call site, not a fifth role

A naive rule ("never sum an intensive measure") would flag two working scripts. The
distinction is NOT a property of the data, because ordinal summation is legal for EVERY
numeric measure, additive and intensive alike. `percentage` is intensive AND ordinally
summable, and a per-semantic enum cannot hold both.

So the role stays a pure function of the semantic, and the API carries the caller's
INTENT:

```python
combine_for_value(rows, col, roles)  # refuses to sum an intensive column
combine_for_rank(rows, col, roles)   # permits any measure; result is ordinal only
```

Independent corroboration that this is the right split, from Flint: its ECharts graph
template sizes each node by SUMMING the edge weight, and for `coupling` that weight is
`degree`, a `Percentage`. A mature charting library does exactly what `dev_network.py`
does by hand. Summing an intensive measure for a radius is idiomatic, not sloppy.

## The four retrofits

Two are VALUE aggregations and are already legal:

```text
digest.py:176-177   sum(added), sum(deleted)   -> both `loc`, additive
                    -> combine_for_value
```

(`digest.py:147` counts `ownership >= 0.999` rather than summing ratios, and
`digest.py:167` takes min/median/max over ages: order statistics are legal on an
intensive measure. Neither needs changing, but check them rather than assuming.)

Two are ORDINAL and sum an intensive column legitimately:

```text
dev_network.py:85-86   strength_total[a] += s   -> `communication.strength`, a percentage
                       used as nodes[].val, a node RADIUS: weighted degree centrality,
                       monotonic in both link count and link strength. No consumer reads
                       the magnitude.
                       -> combine_for_rank

pair_matrix.py:67-68   involvement[a] += w      -> --weight-col, documented as `degree`
                       or `strength`, both percentages. Used ONLY for
                       sorted(involvement, ...)[:top], selecting which entities appear.
                       The number is never rendered.
                       -> combine_for_rank
```

After the retrofit these two SAY that their number is a ranking key, which is currently
inferable only by tracing how the result is used.

## Where roles come from

The optional `--schema FILE` flag, holding `codelens schema --command CMD` output, which
carries a per-command `aggregation_roles` map. Join it against `row_schema[].semantic`.

ABSENT `--schema`, BOTH HELPERS MUST PASS THROUGH WITHOUT ERROR. Graceful degradation is
what made the second input acceptable in the first place (shared decision with spec 003).
That means enforcement is AVAILABLE, not GUARANTEED: an invocation without `--schema` has
no roles to check against. Do not raise, do not warn loudly, do not change behaviour.

This is a real limit on the correctness claim and should not be papered over in the
docstring.

## Conventions

Follow the existing scripts: PEP 723 inline metadata, module docstring with usage and an
exit-code line, `ruff.toml` governs lint, and every script in that directory has a
`*_test.py` beside it. A shared helper module needs one too.

## Acceptance Criteria

- A shared helper providing `combine_for_value` and `combine_for_rank`, with a
  `*_test.py` beside it.
- `digest.py`'s value aggregations use `combine_for_value`.
- `dev_network.py` and `pair_matrix.py` use `combine_for_rank`.
- COMPUTED OUTPUT IS UNCHANGED for all four sites. Verify by diffing generated artifacts
  before and after, not by inspection.
- With roles available, `combine_for_value` REFUSES an intensive column. A test asserts
  that negative case explicitly; it is the guard's entire point.
- With roles available, `combine_for_rank` PERMITS an intensive column.
- Absent `--schema`, both helpers pass through with no error and no warning.
- The docstring states plainly that enforcement requires `--schema` and is therefore not
  guaranteed on every invocation.
- `ruff` clean; `make build` green.
